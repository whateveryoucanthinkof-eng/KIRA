## (a) Verdict

**PARTIALLY — and "partially" is doing almost no work. For the SIH submission: NO.**

Three separate verdicts, because "apply RL" means three different things here:

| Target | Verdict | Reason |
|---|---|---|
| **Branch B — the world model / latent dynamics** | **NO. Do not.** | In *every* canonical world-model system (Ha & Schmidhuber, Dreamer, MuZero, TD-MPC2) the dynamics model is trained by **supervised or self-supervised prediction**. RL trains the *controller*. This repo has no controller, no action space, and no environment that responds to it. Training the dynamics model with RL would be a category error, and a knowledgeable NTRO judge would recognise it as one. |
| **Branch A — risk/technique/stage heads** | **NO.** | Branch A's risk target is a lookup table (`data_unification/multi_dataset_stream.py:288-311`, `TACTIC_BASE_SEVERITY`) keyed on the ground-truth tactic. Re-casting a fully-labelled classification problem as an MDP is the single most common documented anti-pattern in the RL-for-IDS literature. It produces RL-shaped supervised learning with higher variance and no accuracy gain. |
| **A lead-time-aware ALERT-TRIGGERING head (new component)** | **DEFENSIBLE, but not now.** | This is the one place in the system where a genuine sequential decision exists (`WAIT` vs `ALERT` at each 2 s window) and there is real published precedent (EARLIEST, KDD'19). Even here, a 30-line cost-sensitive threshold sweep gets ~80–90% of the benefit, and the honest experiment is to run the sweep *first* and only add the policy if it beats it. |

**The decisive structural argument** (Section b.1 develops it): the system's output does not change the system's input. A predicted ATT&CK stage does not alter the attacker's next packet. Transitions are exogenous. That collapses the "MDP" to a contextual bandit — and because the dataset is fully labelled, every action's reward is observable offline, which makes it a **full-information** bandit, which *is* supervised learning. Policy gradient on top of that adds sampling variance and buys nothing. The only sub-problem where this collapse does **not** happen is the halting decision, because choosing to wait changes which observation you act on and what the cost is.

**For the competition specifically:** `ps.md` never mentions reinforcement learning. Its evaluation list is F1/precision/recall/FPR vs a logistic-regression baseline, explainability, MITRE stage mapping, flow+packet feature combination, a ≤2-page architecture doc, a ≤2-min video and ≤5 slides. File 02 §D lists six items rated **Extreme leverage** at ≤1 day each, three of which are currently **Critical** failures a judge finds without reading code. RL touches none of them. Every hour spent on RL is an hour not spent closing a gap that is actually scored.

## (b) Research findings

### b.1 World models + RL: which half is which

This matters more than anything else in this report, because **the repo already has the world-model half and is missing the half that RL trains — and it is missing it for a good reason.**

**Ha & Schmidhuber, "World Models" (2018)** — three components, three *different* training regimes:
- **V (VAE)**: unsupervised, trained on ~10,000 randomly-played episodes, reward-independent.
- **M (MDN-RNN)**: **supervised** next-latent prediction, `P(z_{t+1} | a_t, z_t, h_t)`.
- **C (Controller)**: ~867 parameters, trained with **CMA-ES** (evolution strategy) against total episode reward. This is the only part where reward enters, and it is deliberately tiny — the whole point of the paper is that the expensive parts are learned *without* reward.
  - https://arxiv.org/abs/1803.10122 · full text: https://www.cl.cam.ac.uk/~ey204/teaching/ACS/R244_2022_2023/papers/ha_arXiv_2018.pdf · reference implementation: https://github.com/ctallec/world-models

**DreamerV3 (Hafner et al.)** — same split, made explicit:
- **World model** (RSSM: encoder, dynamics predictor, reward predictor, continue predictor): trained by **supervised** learning on replayed real trajectories, predicting next latent state, reward and termination.
- **Actor-critic**: trained **entirely inside imagination** — rollouts generated by the frozen world model, no further environment interaction. Actor by REINFORCE-style policy gradient, critic by λ-returns.
  - https://github.com/danijar/dreamerv3 · https://vitalab.github.io/article/2023/01/19/DreamerV3.html · https://www.emergentmind.com/topics/dreamerv3

**MuZero** — the interesting counter-case, and the one most likely to be misapplied here. MuZero's dynamics network is *not* trained to reconstruct or predict the next state at all. Its learning signal comes **only** from predicting future **reward, value and policy** — a "value-equivalent" model that captures only what matters for planning. Losses: policy + value + reward.
  - https://arxiv.org/html/2306.00840v4 ("What model does MuZero learn?") · https://www.idi.ntnu.no/emner/it3105/lectures/search/muzero.pdf · https://arxiv.org/pdf/2011.04021

  **Why MuZero does not transfer here:** value-equivalence is only meaningful when there is a value — a return accumulated by an agent whose actions change the future. Strip out the agent and "value-equivalent dynamics" has no definition. The PS explicitly asks for `P(S_t+1 | S_t)` — *observation*-equivalent dynamics, which is precisely what MuZero deliberately discards. Copying MuZero here would move the system **away** from the stated requirement.

**TD-MPC2** — five components: encoder, latent dynamics, reward predictor, terminal value (critic), policy prior (actor). Decoder-free implicit world model; dynamics learned jointly with reward/value via TD, planning by MPC in latent space.
  - https://arxiv.org/abs/2310.16828

**And the control case — world models with no RL at all.** V-JEPA 2 pre-trains encoder + predictor purely self-supervised on video, then plans with it. There is no policy-gradient step in the world-model training loop.
  - https://ai.meta.com/research/vjepa/ · survey: https://arxiv.org/html/2411.14499

**Applied to this repo.** `HostWorldDynamicsTransformer` is structurally the Dreamer *dynamics predictor* / Ha & Schmidhuber *M*. Its supervised training (`scripts/retrain_future_models_live.py:59-62`: `wdt.rollout(h, K=8)` → discounted multi-horizon MSE + BCE on the risk head) is **exactly the regime those papers use for this component.** The repo is not missing RL; it is missing the *agent* that RL would train — because the PS does not ask for one. PS deliverables are "infiltration probability score, predicted MITRE ATT&CK stage, and top contributing traffic features" — a forecast and an explanation, not a response action.

**The formal collapse.** An MDP requires `P(s_{t+1} | s_t, a_t)` to actually depend on `a_t`. Here the "action" is emitting a risk score / stage label to a dashboard; the attacker's next packet is unaffected. A decision process whose state transition is independent of the agent's action is, by definition, a contextual bandit (a special case of a POMDP where the world-state transition function is independent of the agent's action) — see Murphy, *Reinforcement Learning: An Overview*, https://arxiv.org/pdf/2412.05265. And contextual bandits with **full-information** feedback — which is what an offline labelled dataset gives you, since you can compute the reward of *every* possible prediction for *every* window — are equivalent to supervised learning; the practical frameworks literally reduce them to repeated calls to a supervised regression oracle (https://jmlr.org/papers/volume22/18-863/18-863.pdf, https://arxiv.org/pdf/2301.00241).

This is not a stylistic objection. It means a policy-gradient estimator on Branch A/B would be a **higher-variance Monte-Carlo estimate of a gradient the supervised loss already computes exactly.**

### b.2 RL vs scheduled sampling / DAgger for multi-step rollout error

Compounding rollout error is a *real* problem for K-step autoregressive forecasters, and it is the strongest-sounding motivation for RL here. The literature says the fix is imitation/curriculum, not RL.

- **Exposure bias is covariate shift**, not a reward problem: models are trained under teacher forcing on observed prefixes but deployed on their own predictions, so early errors perturb later inputs and compound. https://arxiv.org/pdf/2606.12990
- **Scheduled sampling** (Bengio et al., NeurIPS 2015): mix ground-truth and model-predicted inputs with an annealed probability. https://arxiv.org/abs/1506.03099 · https://www.researchgate.net/publication/278048447
- **Professor forcing** (Lamb et al., NeurIPS 2016): adversarial matching of the hidden-state distributions under teacher forcing and free running.
- **DAgger** (Ross, Gordon & Bagnell, AISTATS 2011): roll out the learner, query the expert at the learner-induced states, aggregate, retrain. https://arxiv.org/abs/1011.0686
- **Flipped Classroom** (Teutsch & Mäder, 2022) — the most directly relevant, and it complicates the naive story. Verified abstract: *"TF can be used to help the model converge faster but may provoke an exposure bias issue... FR helps to avoid this but does not necessarily lead to better results, since it tends to make the training slow and unstable instead... even if parametrized carefully, scheduled sampling may lead to premature termination of the training when applied for time series forecasting."* Their proposed increasing-training-scale curriculum gives **up to 81% NRMSE improvement over FR or TF**, plus higher prediction stability at long horizons. https://arxiv.org/abs/2210.08959

**Repo-specific finding — this changes the recommendation, verified directly:**

`world_model/training/scheduled_sampling.py` exists and is **imported by nothing**. The only reference anywhere in the repo is prose in `TECHNICAL_REVIEW.md:558`. It is dead code.

More importantly, **Branch B does not have the exposure-bias problem scheduled sampling is designed to fix.** `train_branch_b.py:113` and `scripts/retrain_future_models_live.py:59` call `wdt.rollout(h_hist, K=8)`, and `rollout()` (`branch_b_world_model/rollout_encoder_decoder.py:188-236`) feeds each prediction back as context with **no `detach()`** — gradients flow through the entire K-step chain. Branch B is already trained in **pure free-running mode with full BPTT**. Train and test distributions already match.

So:
- Applying scheduled sampling to Branch B **in the standard direction (TF → FR) is a no-op**, because Branch B is already at 100% FR.
- What Flipped Classroom predicts Branch B *actually* suffers from is the other failure mode: **pure-FR training is slow and unstable**. The correct fix is a curriculum in the *opposite* direction — teacher-forced warm-up, then increasing free-running scale.
- **DeepOP is the component with real exposure bias.** `scripts/retrain_future_models_live.py:89` trains the CWA decoder with pure teacher forcing (`<BOS>` + gold prefix → `F.cross_entropy`, `deepop_decoder/train_cwa_decoder.py:27-28,181-194`), while `forecast_decoder.py:296-301` decodes greedily from its own argmax at inference. Classic train/test mismatch. This is where `scheduled_sampling.py` should have been wired, and never was.

**Verdict on this axis:** the compounding-error argument does not support RL. It supports a curriculum, and it identifies a *different component* than the one people assume.

### b.3 RL in cyber defence: what actually works, and what goes wrong

The RL-in-cyber literature is large and splits cleanly into two halves, and only one half is about anything this repo does.

**Half 1 — autonomous cyber *defence* (RL is genuinely the right tool).** CybORG / CAGE, CyberBattleSim, FARLAND. Here an agent takes real actions (isolate host, restore service, deploy decoy) that change the environment. A real MDP.
- CAGE Challenge 4 (MARL, blue team vs red team vs green users): https://github.com/cage-challenge/cage-challenge-4 · https://onlinelibrary.wiley.com/doi/full/10.1002/aaai.70021
- PPO dominated CAGE-2 submissions (agents 1–6 exclusively PPO, four hierarchical): https://arxiv.org/pdf/2309.07388
- CybORG++: https://arxiv.org/pdf/2410.16324
- CyberBattleSim (post-breach lateral movement, deliberately abstract): https://github.com/microsoft/CyberBattleSim · https://www.microsoft.com/en-us/research/project/cyberbattlesim/
- FARLAND (high-fidelity network simulation, but does not simulate host state), per https://arxiv.org/pdf/2303.04926

**None of this applies.** This repo's output is a dashboard number. There is no action, no blue agent, no environment to close the loop with. Building a CybORG-style RL environment for it means building the response half of a product the PS did not ask for.

**Half 2 — RL for *intrusion detection* (the anti-pattern).** The canonical work is Lopez-Martin, Carro & Sanchez-Esguevillas, *Application of deep reinforcement learning to intrusion detection for supervised problems*, Expert Systems with Applications 141:112963 (2020). Their own framing is the tell: they make *"a conceptual modification of the classic DRL paradigm (based on interaction with a live environment), replacing the environment with a sampling function of recorded training intrusions."* They state the motivating problem plainly — *"the implementation of a reward function aligned with the detection of intrusions is extremely difficult... since there is no automatic way to identify intrusions."*
- https://www.sciencedirect.com/science/article/abs/pii/S0957417419306815 · open copy: https://uvadoc.uva.es/bitstream/10324/54271/1/Application-of-deep.pdf
- Surveys: https://arxiv.org/html/2410.07612v1 · https://link.springer.com/article/10.1007/s42979-024-03001-1

Replacing the environment with a sampler over a labelled dataset **is** the contextual-bandit collapse of b.1, implemented. The resulting "agent" is a classifier trained by a noisier optimiser.

**Documented failure modes — the skeptical anchor.** *SoK: The Pitfalls of Deep Reinforcement Learning for Cybersecurity*, McFadden, Foley, Bates, Tsingenopoulos, Vyas, Mavroudis, Hicks & Pierazzi (USENIX Security 2026). They analysed **66 papers (2018–2025)** and found an average of **5.8 methodological pitfalls per paper**; **every** paper had at least two.
- https://arxiv.org/abs/2602.08690 · https://arxiv.org/html/2602.08690v1 · https://www.usenix.org/conference/usenixsecurity26/presentation/mcfadden

The 11 pitfalls, with the five this repo would walk straight into marked:

The SoK's own recommendation: *"DRL is not suitable for all tasks"*, and applying it should *"be justified theoretically and, when possible, empirically."* It also notes that *"direct and fair comparisons to existing approaches in the domain can be infeasible when reformulating through a DRL paradigm"* — i.e. adopting RL would make the PS's own required logistic-regression comparison *harder* to state honestly.

**Sim-to-real.** Low-fidelity environments produce **simulator artifacts** — agents that score well in sim and behave unpredictably in reality; the gap has two components, environment virtualisation and task modelling (https://arxiv.org/pdf/2309.07388, https://arxiv.org/pdf/2410.16324). This repo would need a simulated attacker to generate on-policy data. Its only attacker is `workloads/attacker_scenario.py`, a scripted cyber-range workload. An RL forecaster trained against a *scripted* attacker learns that script. That is the artifact failure mode by construction — and worse for the PS, it directly contradicts requirement 6 ("generalise to unseen attack patterns", already **MISSING/unproven** per file 02 §A).

**Reward hacking.** Structural, worsens with agent capability, and can appear as a phase transition with little warning even when average proxy/true reward correlation is tight; policy anomaly detection gives only partial protection. https://arxiv.org/html/2604.13602v1 · https://arxiv.org/pdf/2507.05619 · https://www.emergentmind.com/topics/reward-hacking

### b.4 GRPO / RLVR: is there a verifiable reward here?

**Yes, a verifiable reward is definable. No, it does not make GRPO the right tool.**

The reward *is* verifiable in the RLVR sense: for a window at time `t`, the realized ATT&CK token at `t+k` is known from the dataset annotations, so "did the predicted stage actually occur K steps later" is a checkable, non-gameable, ground-truth predicate. That much is real.
- GRPO mechanics: https://cameronrwolfe.substack.com/p/grpo · https://arxiv.org/html/2503.06639v1 · https://github.com/opendilab/awesome-RLVR

Five reasons it does not transfer:

1. **Full-information feedback again.** RLVR's leverage in LLM reasoning is that you cannot supervise the *chain of thought* — only the final answer — so you need a policy-gradient estimator. Here there is **no unsupervised intermediate**: the label for every window at every horizon is in the dataset. You can supervise the thing you would otherwise have to reward. Cross-entropy is the exact gradient; GRPO is a sampled approximation of it.

2. **Graded, not binary.** RLVR/GRPO work best when rewards are near-binary (correct/incorrect). Forecasting quality is continuous and graded under MSE/MAE, and group-relative advantage normalisation can assign positive advantage to merely *less-bad* samples when a whole sampled group is mediocre — producing misleading gradients. *(This framing surfaced repeatedly in the 2026 time-series-RLVR literature — see* TimeRFT*, Li et al., https://arxiv.org/pdf/2605.00015, and* PostTime*/Rethinking Post-Training Recipes for Multimodal Time-Series Forecasting, Liu, Zhou, Sen, Prakash & Das, https://arxiv.org/abs/2605.29401. I was unable to extract the exact sentence from either PDF, so treat the specific wording as unverified and the argument as mine.)*

3. **Group collapse in a 7-token vocabulary.** `deepop_decoder/joint_vocab.py:20-28` defines 7 real tokens + 3 special. K=8. GRPO needs *variance within the sampled group* to produce any gradient at all. With a small vocabulary, a heavily Benign-skewed label distribution, and an already near-deterministic decoder (`forecast_decoder.py:296-301` is greedy argmax with a repetition penalty), a large fraction of sampled groups will be **identical**, giving zero advantage and zero gradient — you pay 8–16× the forward compute for a no-op step.

4. **The reward would be computed against a known-broken label map.** File 02 §4: `consolidate_network_technique` has no LateralMovement branch, so lateral-movement records fall through and are **labelled Benign**; `multi_dataset_stream.py:334` injects `T1059`, which is not in `TECHNIQUE_VOCAB` and silently maps to index 0 = Benign. RLVR's entire safety property is that the verifier is correct. **Optimising hard against a verifier that labels lateral movement as benign would actively train the model to predict Benign during lateral movement** — and lateral movement is the phase the demo's own attacker script stages (`workloads/attacker_scenario.py:629-703`). This is reward hacking with the hack already baked into the reward.

5. **The one honest counter-point:** RLVR *is* being applied to forecasting successfully in 2026, in exactly one configuration — post-training a **large language model** to revise a numerical forecaster's prior using multimodal context (PostTime: Gemma-3-4B + TimesFM-2.5, SFT **then** RLVR). That is a different architecture, a different scale, and it still uses SFT first. Nothing in it argues for policy-gradient training of a 3-layer, 64-d transformer on 12-D latents.

### b.5 The reward-design problem

If you did build the one defensible RL component (b.4 aside — this is the halting policy), the reward design has genuine prior art, and it is the **early classification of time series (ECTS)** literature, not the cyber literature.

The canonical ECTS cost function is verified from the survey: the cost of triggering a prediction at time `t` is
`L(ŷ(x_t), y, t) = C_m(ŷ(x_t) | y) + C_d(t)` — misclassification cost plus delay cost.
- Survey & benchmark: *Early Classification of Time Series: Taxonomy of Methods and Extensive Benchmark*, https://arxiv.org/html/2406.18332v4

RL-based members of that family:
- **EARLIEST** — Hartvigsen, Sen, Kong & Rundensteiner, *Adaptive-Halting Policy Network for Early Classification*, **KDD 2019**. LSTM Discriminator + stochastic Controller trained by **policy gradient**, jointly learning what to predict and when to stop. https://dl.acm.org/doi/10.1145/3292500.3330974 · code: https://github.com/Thartvigsen/EARLIEST
- **Martinez et al.**, *A Deep Reinforcement Learning Approach for Early Classification of Time Series* (EUSIPCO 2018) — DQN over the triggering decision. https://ieeexplore.ieee.org/document/8553544/
- Non-stationary end-to-end variants: https://arxiv.org/html/2608.20044 · penalty-based few-shot reward: https://arxiv.org/html/2608.16385

**The critical caveat from that same benchmark** (verified by direct read): the survey's main experiments compare **nine trigger methods**, and the authors *"chose not to evaluate 'end-to-end' methods, leaving that for future work."* The top-performing group they identify consists of **non-RL, cost-based/anticipation methods** — Calimera, ECONOMY-γ-max, TEASER, stopping rules, probability thresholds. **The RL family has not been shown to beat well-tuned cost-based triggers on this exact trade-off.** That is the single most important empirical fact in this whole report for the "should we do RL" question.

**Cyber-side lead-time prior art** (for how to *measure*, not how to optimise):
- Husák, Komárková, Bou-Harb & Čeleda, *Survey of Attack Projection, Prediction, and Forecasting in Cyber Security*, IEEE COMST 2019 — the canonical taxonomy for this PS's whole problem class. https://is.muni.cz/publication/1434138/2019-COMST-survey-of-attack-projection-prediction-forecasting.pdf
- DARKMENTION (deployed enterprise attack prediction; precision/recall/F1 against matched ground-truth events): https://arxiv.org/pdf/1810.12492
- CT-EWS — graph-centric early warning validated on *early-warning lead time*, using an **asymmetric operational loss penalising under-prediction more than over-prediction**. https://www.frontiersin.org/journals/computer-science/articles/10.3389/fcomp.2026.1897752/full
- Review of time-series analysis for cyber security analytics: https://link.springer.com/article/10.1007/s10207-024-00921-0

**A concrete reward, for completeness.** At window `t` with a rolled-out risk trajectory, action ∈ {WAIT, ALERT}:

```
ALERT at t, attack ground-truth onset at t* :
    t <= t*   ->  R = +w_lead * min(1, (t* - t) / L_max)        # lead-time-weighted true positive
    t  > t*   ->  R = +w_late                                   # correct but no lead time
    no attack ->  R = -c_fp                                     # false-positive penalty
WAIT         ->  R = -c_wait                                    # delay cost C_d(t)
episode ends with attack never alerted -> R = -c_miss
optional calibration term: -lambda * (p_pred - y)^2             # Brier / proper scoring rule
```

Note that `w_lead`, `w_late`, `c_fp`, `c_wait`, `c_miss`, `lambda` are **six free hyperparameters** with no principled setting, and the resulting operating point is far more sensitive to them than to the choice of optimiser. That is the reward-design problem in one line: **you are not learning a policy, you are hand-picking a point on a Pareto curve and then paying an RL algorithm to find it.** A grid search over a single threshold finds the *whole curve* for less compute.

Useful repo fact: the measurement machinery already exists. `world_model/evaluation/forecasting_metrics.py:14,29,48-56` computes mean/median lead time in seconds; `world_model/evaluation/detection_metrics.py:25,74` computes precision/recall/F1/AUROC and `fpr_at_95_tpr`; `world_model/evaluation/calibration.py:17,69-84` has calibration metrics **and a temperature-scaling module**. All three depend only on two missing constants (file 02 §B3). You can build the entire earliness/FPR Pareto evaluation with zero RL and mostly existing code.

### C1. Lead-time-aware alert-triggering head (EARLIEST-style halting policy) — the only genuinely RL-shaped sub-problem

**Why this one is real:** choosing to WAIT changes which observation you next act on and accumulates delay cost. Credit assignment across time is non-trivial. This is not the contextual-bandit collapse of b.1.

**Design:** freeze TGNE-TA, Branch A, Branch B and the risk head. Add a small controller (2-layer MLP, ≤5k params) over `[h_t, rollout risk trajectory (K=8), hazard features]` emitting `Bernoulli(p_halt)`. Train with REINFORCE + a learned baseline on the reward in b.5. Everything upstream stays supervised — this mirrors Ha & Schmidhuber exactly (tiny controller, frozen world model).

**Files that would change:**
- **NEW** `branch_b_world_model/halting_policy.py` — controller module + REINFORCE loss.
- **NEW** `scripts/train_halting_policy.py` — episode construction from `HostTrajectoryExtractor` trajectories; reward from ground-truth onset times.
- `world_model/evaluation/forecasting_metrics.py` — reuse `compute_forecasting_metrics` (`:14`) for the lead-time term; add the two missing constants.
- `control_backend/model_adapter.py:340-400` — consume `p_halt` for the alert flag instead of the current heuristic block. **Prerequisite: file 02 §B2's override (`:350-362`) must be deleted first, or the policy is trained against a rule-based label, not the model.**
- `config/temporal_contract.json` — record the cost weights so the operating point is reproducible.

**Non-negotiable gate:** the non-RL threshold sweep (D2 below) must be run **first** and reported as the baseline. If the policy does not beat it, publish that. A clean negative result against a tuned baseline is a stronger submission artifact than an unbaselined RL number, and it directly pre-empts SoK pitfall **E-GA**.

**Cost:** 3–5 days including the baseline, plus one day of seed-variance runs (SoK **T-VA**).

### C2. DeepOP sequence-level reward — only *after* scheduled sampling, and only if SS is insufficient

**Why second:** DeepOP is the repo's only autoregressive discrete generator with genuine exposure bias (b.2), and sequence-level rewards are the standard remedy when token-level cross-entropy misaligns with the sequence metric you care about. But see b.4(3) — group collapse on a 7-token vocabulary is a serious practical risk, and b.4(4) — the verifier is currently wrong.

**Hard precondition (also independently required by file 02 §4):** fix `deepop_decoder/joint_vocab.py:31-74` `consolidate_network_technique` to have a LateralMovement branch, add `T1021` to the vocab, add lateral-movement rows to `data_unification/label_maps/*.csv`. **Files:**
- `deepop_decoder/joint_vocab.py:20-74` — vocab + consolidation fix (do this regardless of RL).
- `deepop_decoder/forecast_decoder.py:219-320` — add a `sample_sequence()` path (multinomial, not greedy argmax) to generate the GRPO group.
- **NEW** `deepop_decoder/train_cwa_grpo.py` — group sampling, exact-match / edit-similarity reward, group-relative advantage, KL penalty to the SFT reference.
- `scripts/retrain_future_models_live.py:76-94` — chain SFT → SS → (optional) GRPO.

**Cost:** 4–6 days. **Expected gain: low.** I would not do this.

### C3. Nothing else

Do **not** apply RL to Branch A, Branch B dynamics, or TGNE-TA. Sections b.1 and b.3 cover why. Branch A's actual problem is class imbalance (99.94% technique accuracy at epoch 5, file 01 §6) — the fix is focal loss / reweighting / a proper held-out split, not a different optimiser.

## (d) What would go wrong — and the cheaper thing that gets 80%

### What goes wrong

1. **You would train against a scripted attacker and call it generalisation.** On-policy RL needs an environment. The only one available is `workloads/attacker_scenario.py`. An agent trained against a fixed script learns the script's timing. This is the documented simulator-artifact failure (https://arxiv.org/pdf/2309.07388) and it makes PS requirement 6 *worse*, not better, while appearing to address it.

2. **The reward would be computed against a verifier that is known to be wrong.** LateralMovement → Benign (file 02 §4). Optimising hard against it teaches the model to go quiet during lateral movement. Reward hacking with the hack pre-installed.

3. **Gain attribution becomes unfalsifiable.** With `model_adapter.py:350-362` still overriding risk and technique on the live path, no observed improvement can be attributed to the policy. SoK **E-GA**, present in a large share of the 66 papers surveyed.

4. **Variance eats the schedule.** Policy gradient needs multi-seed runs to make any claim; SoK **T-VA** and **T-PC** (71.2% prevalence) are the two most common pitfalls precisely because teams run out of time. A 3-epoch budget (current: `--epochs 3`) is not an RL budget.

5. **You lose the PS's own baseline comparison.** SoK: *"direct and fair comparisons to existing approaches in the domain can be infeasible when reformulating through a DRL paradigm."* `ps.md:50` requires comparison against logistic regression **on the same features**. Adding an RL layer makes that table harder to construct and easier for a judge to poke.

6. **Reward hacking is structural and can appear without warning** — phase transitions even under tight average proxy/true correlation. https://arxiv.org/html/2604.13602v1

7. **A judge asks "why RL?" and there is no good answer** — because the honest one is "the dynamics model in Dreamer and Ha & Schmidhuber is trained supervised, and we have no policy."

## (e) Recommendation for the SIH submission timeline

**Do not do training-time RL for this submission. It will not help you win, and it will cost you the things that would.**

### Why it will not help you win

- `ps.md` does not mention reinforcement learning once. Not in the description, not in the architecture section, not in the deliverables, not in the evaluation criteria.
- The listed evaluation artifacts are: **F1 / precision / recall / FPR vs logistic regression on the same features**; explainability (attention or SHAP, "black-box outputs without interpretability are not acceptable"); MITRE stage mapping to five named phases; the flow+packet combination (the only place the PS uses the word **"required"**); a ≤2-page architecture doc; a ≤2-min video; ≤5 slides.
- File 02 §A scores three of those **MISSING** and four **PARTIAL**. Three are failures a judge finds in under ten minutes without reading code: a disconnected explainability panel, a heuristic override on the headline risk number, and **zero F1/precision/recall/FPR anywhere in the repo**.
- File 02 §D lists six **Extreme/Very-high leverage** items at ≤1 day each. RL addresses none of them, and item #3 (delete the heuristic override, ~1 h) is a hard **prerequisite** for RL being meaningful at all.

### The blunt arithmetic

An RL programme costs, realistically: 1 day defining the MDP, 2 days on the reward and its hyperparameters, 3–5 days implementing and debugging the policy gradient, 2 days on multi-seed variance runs, 1 day on the baseline you must run anyway. **~9–11 days.** The competing spend: **D1 + D2 + D6 = 2 days**, plus file 02's top six = **~4 days**. Six days closes every Critical gap *and* delivers the probabilistic world model, the lead-time Pareto curve and calibration. Eleven days of RL delivers one number with wide error bars and a new set of questions you cannot answer.

### The 20-minute move that captures the entire RL upside

Write one paragraph in the rewritten `docs/ARCHITECTURE.md` (which needs rewriting anyway, file 02 §10) titled **"Why supervised dynamics learning, not reinforcement learning."** Say:

> In Ha & Schmidhuber's World Models, DreamerV3 and TD-MPC2, the latent dynamics model is trained by supervised or self-supervised next-state prediction; reinforcement learning trains only the controller that acts on it. Our system is a forecasting and decision-support component, not an autonomous responder: its predictions do not alter the network's state, so the transition dynamics are exogenous and the decision process degenerates to a full-information contextual bandit — provably equivalent to supervised learning. We therefore train `P(S_t+1|S_t)` by supervised dynamics learning with a Gaussian likelihood, exactly as the problem statement specifies, and select the alert operating point by cost-sensitive threshold optimisation over the earliness/false-positive Pareto frontier (Early Classification of Time Series, cost `C_m + C_d`) rather than by policy gradient, which the ECTS benchmark literature does not show to outperform well-tuned cost-based triggers.

That paragraph turns "why no RL?" from a vulnerability into a demonstration that the team read the world-model literature carefully enough to know which half of it is RL. It is worth more in a viva than a half-converged policy.

### If there is spare capacity in the final week

Only after every Critical and High item in file 02 §D is closed, and only if ≥4 days remain: build **C1** (the halting policy) **with D2 as its published baseline**, and report the comparison honestly in both directions. Frame it as *cost-sensitive alert triggering*, cite EARLIEST (KDD'19), and state the cost weights explicitly. If the policy loses to the threshold sweep, say so — that is a defensible research result and it inoculates you against SoK pitfalls **E-AM** and **E-GA**. Under no circumstances put RL on the critical path.
