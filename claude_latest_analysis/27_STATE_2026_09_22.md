## The single most important open question

**Does Branch B beat persistence?** Its first full run plateaued at epoch 1
(train loss moved 1.9% over 6 epochs; best validation was epoch 1). That is
equally consistent with three diagnoses needing opposite fixes: the task is
trivial, the model underfits, or the target is uninformative.

The running Branch B job now prints, every epoch:

```
embeddings: mse_model=... mse_persistence=... skill=...
risk: bce_model=... bce_constant=... mae_model=... mae_predict_zero=...
```

`skill = 1 - mse_model/mse_persistence`. **Negative or near-zero skill means
the world model is not learning dynamics**, and then DeepOP — which trains on
its rollouts and cannot exceed it — needs rethinking, not tuning.

## Fixed this session (all committed, 523+ tests green)

**Branch A's risk head was worse than predicting zero** (MAE 0.2268 vs
0.1334). Two causes: the head had converged to the unconditional mean (the
smooth-L1-optimal constant is 0.1400, MAE 0.2279 — a match to 0.0011), and
smooth L1 is mean-seeking while MAE is median-seeking on a target that is 0
for 82.5% of samples, so it could never have won. Now `--risk-objective bce`
predicts P(attack next window), judged by AUC/Brier/ECE from a 2000-bin
histogram (verified against sklearn to 6e-6).

**The risk target itself was the root cause** — `base_severity(tactic) +
0.04*density + 0.04*volume`, i.e. not a forecast, nearly a function of the
category another head predicts, and bimodal. `TrajectoryStore.hazard_risk(tau)`
= `exp(-seconds_to_next_attack / tau)` replaces all three problems: 15.5%
zeros instead of 82.5%, 33 distinct values instead of 2. **Not wired into any
trainer** — that changes what the models learn and deserves a measured A/B.

**Checkpoint selection was invalid** — val loss contains learned log-variance
terms that drifted 0 → −7.04, so epochs were not comparable. Selecting the
minimum picked an outlier epoch that generalised worst. Now
`0.5*macro_f1 + 0.5*risk_auc`.

**Serving would have gone silent.** The adapter alerts at a hardcoded 0.65
chosen for the old severity scale; against a calibrated probability on a 17.5%
base rate that fires on <2% of windows and recalls <15% of attacks. It now
reads a fitted `operating_point` from the checkpoint and warns loudly when one
is missing. `_alert_level` also had an unreachable WARNING branch.

**Train/serve parity now actually verified** — 300 real windows, 89,212 flows,
52,661 hosts, worst deviation **0.000e+00**. The check had only ever run
against an empty fixture and reported "cannot assert parity".

**Other:** two of three log-variance parameters were frozen (clamp passes no
gradient outside bounds); `compute_loss` did 7 host-device syncs per batch
(~1.1M/epoch); the downstream retrain wrote to a path nothing loads; it also
held a whole 32.5M-record split in RAM and thrashed at 57.7% stalled; DeepOP
recomputed a frozen rollout worth 25.4% of its wall clock.
